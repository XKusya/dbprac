1. В чем отличие первичного ключа и уникального индекса?

Первичный ключ - уникальный индекс + NOT NULL + один на таблицу.
Уникальный индекс - только гарантирует уникальность значений, но допускает NULL (и их может быть несколько), и их может быть несколько на таблиц

2. В каких случаях имеет смысл создавать индексы? Какие колонки следует включать в индекс и почему?
    - Частые фильтры в WHERE (date_id = ... AND competition_id = ...)
    - JOIN'ы
    - Ускорение сортировки 
    - если по фильтру понятно, что будет отсеяно много строк

3. Какие существуют способы внутренней организации индексов?
    - Бинарное дерево
    - Хэш-Таблицы
    - GIN (Инвертированный индекс, значение -> список из id, часто используется для JSON, массивов и поиска по тексту)
    - GiST (иерархическое дерево, подходит для геоданных POINT, POLYGON)
    - SP GiST 
    - BRIN (индекс по блокам данных, подходит для очень больших таблиц, где есть сравнение диапазонов)

4. Что такое фрагментация индексов?
При частых обновлениях бд индекс портится. 
«Мёртвые» записи (например, после UPDATE review в Competition — старые значения индекса остаются).
логически соседние ключи находятся на разных дисковых блоках → больше I/O и тому подобное. 
Боротся с этим достаточно просто, просто удалить и сделать новый такой же индекс. 
Или использовать REINDEX (REINDEX INDEX CONCURRENTLY idx_performance_date_id)

5. Влияет ли порядок столбцов в индексе?
Да, влияет.
сначала фильтры по равенству → потом диапазоны → потом сортировка/агрегация. 
если допустим индекс (A, B, C), то должны быть сравнения А в начале, потом B, потом C

8. Зачем ANalyze?
PostgreSQL собирает статистику по содержимому таблиц 
(распределение значений, количество строк, корреляция, частота NULL и т.д.) 
и сохраняет её в системную таблицу (pg_statistic).
